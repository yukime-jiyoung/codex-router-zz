# Codex に外部モデルを、実測で入れる

*[English](README.md)*

ChatGPT の Codex アプリのモデル選択欄に、OpenAI 以外のモデルを追加します。追加したモデルは既存の選択欄からそのまま選べて、**同じ会話の途中で GPT と行き来できます**。再起動も設定編集もコマンドも要りません。

これは [codex-router](https://github.com/duolahypercho/codex-router)（MIT）に、OpenCode Zen 経路と、その過程で見つけた互換性の修正を加えたものです。

---

## このプロジェクトが他と違うところ

**「対応しています」と書く代わりに、送って確かめた記録を置いています。**

`README` に「tools 対応」と書いてあるモデルが、実際には特定の形のツール定義を拒否する。そういうことが起こります。私たちは 2 日かけてそれに当たり、原因を特定し、記録しました。

### 実測した結果（muse-spark-1.3-contributor-free / 2026-09-11）

| 送ったもの | 返ってきたもの |
|---|---|
| 関数ツールに `strict: true`、任意の引数を `required` に含めない | **400** |
| 同じものから `strict` を外す | 200 |
| `tool_choice` に関数名を指定 | **400**（`auto` のみ受理） |
| `tool_choice: "none"` | **400** |
| freeform な `custom` ツール | **400** |
| `stream: false` の本文に `stream_options` が残っている | **400** |
| ツール呼び出しの `arguments` が空文字列 | **400** |
| 同じく `"{}"` | 200 |
| `web_search` ツールを渡す | 200・**実際に検索を実行した** |
| 完了済みの検索記録を履歴に含める | 200 |
| 約 22 万トークンの入力 | 200 |

最後から 5 番目が特に厄介でした。引数を取らないツール（一覧取得など）を呼ぶと、Codex は `arguments` を空文字列で記録します。OpenAI はこれを受理しますが、この経路は拒否します。**その項目は毎ターン再送されるため、一度混入すると会話が二度と続かなくなります。** 利用者からは「急に壊れた」としか見えません。

これらはすべて修正済みです。そして**同じことを自動で調べる道具を同梱しています**。

### 自分で確かめられます

```sh
node tools/compat-probe/probe.mjs --model <プロバイダ>/<モデル> --tier full
```

対照実験を組んで送ります。1 回の試験で変える条件は 1 つだけ。たとえば `strict` の試験なら、同じスキーマで `required` の中身だけを変えた 2 通りを送り、結果の差を見ます。

出力はそのまま使える設定ファイルで、各項目に「いつ、何を送って、何が返ったか」が付きます。

```json
{
  "toolStrictMode": "drop",
  "_evidence": {
    "test_id": "T_TOOL_STRICT_REQUIRED_001",
    "tested_at": "2026-09-11T...",
    "request": "strict:true の関数ツール、required が limit を含まない",
    "response": "HTTP 400 invalid_request_error param=tools",
    "control": "同じスキーマから strict を外すと 200"
  }
}
```

**受理されただけでは「対応」と判定しません。** パラメータを受け取って黙って捨てる相手がいるからです。400 は気づけますが、200 を返して無視されると、本番で「なぜか検索しない」という形でしか現れません。そこで、パラメータが効いたかどうかが応答に現れる課題と必ず組にして送り、4 通りに分類します。

| 対照（指定なし） | 変種（指定あり） | 判定 |
|---|---|---|
| 効果なし | 効果あり | 効いている |
| 効果あり | 効果あり | 常に有効（指定は冗長） |
| 効果あり | 効果なし | 指定すると消える |
| 効果なし | 効果なし | **黙って無視されている** |

2 番目と 4 番目を区別しない道具は、正常な相手を「壊れている」と報告します。実際に一度やりました。

### 会話をまたいだ切り替え

GPT の思考内容は暗号化されていて他社のモデルへ渡せません。そのままでは、モデルを切り替えた瞬間に会話が途切れます。

この実装では、会話の要約を**両方のモデルが読める形式**に変換します。結果として、GPT が決めた条件を、切り替えた先のモデルがそのまま引き継げます。

実際の確認手順と結果です。

1. GPT に 4 桁の数字を 1 つ選ばせ、それを含むファイルの仕様を決めさせる
2. Muse に切り替えて「さきほど GPT が決めた条件どおりに」とだけ伝える
3. Muse が `# alpha-4729` を含む 8 行のファイルを作成
4. GPT に戻して検証させる → 合格

`4729` は人間が指定していません。会話が渡っていなければ出てこない数字です。途中で自動要約が 3 回走っていますが、条件は保持されました。

## 入れる

Node.js 24 以上。macOS・Linux・Windows。

```sh
git clone https://github.com/suzukitakumi-hub/omc-codex.git
cd omc-codex
./install.sh codex
```

Codex を起動すると、モデル選択欄に追加されています。

## 正直に書いておくこと

**無料枠は学習に使われる可能性があります。** `muse-spark-1.3-contributor-free` は、入力と出力が Meta のモデル学習に使われる可能性があると提供元が示しています。過去の会話やツールの実行結果も含まれます。**業務の機密情報を入れないでください。**

**上限は不明です。** 課金はされませんが、無制限という確認は取れていません。開発中に `429` が出ています。具体的な上限値も解除時刻も分かっていません。

**未検証の項目があります。** コンテキスト長 `1048576` は公開メタデータの値で、実測では 22 万トークンまでしか確認していません。`tool_choice: "none"` は拒否されますが未対応のまま残っています（有料経路で約 100 ターン動かして発生しなかったため）。

**プロキシ経由の利用を制限する提供元があります。** 提供元の規約・レート制限・アカウント処分から利用者を守るものではありません。いずれの提供元とも提携していません。

## 仕組み（簡単に）

Codex は本来 OpenAI のサーバーに話しかけますが、設定を変えて**自分の PC 上の中継役**に話しかけさせます。中継役が中身を見て、GPT なら OpenAI へ、それ以外なら該当の提供元へ送り分けます。形式の違いもここで吸収します。

だから Codex 側は「いつもどおり」動いているつもりのまま、別のモデルが答えます。切り替えが一瞬なのはこのためです。
