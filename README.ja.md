# Codex に外部モデルを、実測で入れる

*[English](README.md)*

ChatGPT の Codex アプリのモデル選択欄に、OpenAI 以外のモデルを追加します。追加したモデルは既存の選択欄からそのまま選べて、**同じ会話の途中で GPT と行き来できます**。再起動も設定編集もコマンドも要りません。

これは [codex-router](https://github.com/duolahypercho/codex-router)（MIT）に、OpenCode Zen 経路と、その過程で見つけた互換性の修正を加えたものです。

---

## このプロジェクトが他と違うところ

**「対応しています」と書く代わりに、送って確かめた記録を置いています。**

`README` に「tools 対応」と書いてあるモデルが、実際には特定の形のツール定義を拒否する。そういうことが起こります。私たちは 2 日かけてそれに当たり、原因を特定し、記録しました。

> **2026-09-17 追記。** OpenCode が無料枠を自社クライアント以外から遮断しました（`OpenCode's free tier can only be used from within OpenCode`）。下の表は無料経路に対する 2026-09-11 の実測ですが、**同じ 2 日後の測定で有料の `muse-spark-1.3` が同一の挙動を示すことを確認済み**です。経路の設定はそのまま有効で、選ぶモデルが無料版から有料版に変わります。

### 実測した結果（muse-spark-1.3-contributor-free / 2026-09-11）

| 送ったもの | 返ってきたもの | このリポジトリでの扱い |
|---|---|---|
| 関数ツールに `strict: true`、任意の引数を `required` に含めない | **400** | `strict` を外して送る |
| 同じものから `strict` を外す | 200 | — |
| ツールの定義が `$ref` で自分自身を参照する | **400** | 参照を展開してから渡す |
| `tool_choice` に関数名を指定 | **400**（`auto` のみ受理） | `auto` に書き換える |
| `tool_choice: "none"` | **400** | **未対応（あとで述べます）** |
| freeform な `custom` ツール。Codex は `apply_patch` をこの形で送る | **400** | 通常の関数ツールに変換し、戻りで元の形へ復元 |
| `stream: false` の本文に `stream_options` が残っている | **400** | 本文から取り除く |
| ツール呼び出しの `arguments` が空文字列 | **400** | `"{}"` を補う |
| 同じく `"{}"` | 200 | — |
| `web_search` ツールを渡す | 200・**実際に検索を実行した** | 有効にしてある |
| 完了済みの検索記録を履歴に含める | 200 | そのまま通す |
| 約 22 万トークンの入力 | 200 | — |

`arguments` が空文字列の行が特に厄介でした。引数を取らないツール（一覧取得など）を呼ぶと、Codex は `arguments` を空文字列で記録します。OpenAI はこれを受理しますが、この経路は拒否します。**その項目は毎ターン再送されるため、一度混入すると会話が二度と続かなくなります。** 利用者からは「急に壊れた」としか見えません。

拒否された 7 件のうち 6 件を修正済みです。残る 1 件（`tool_choice: "none"`）は未対応で、理由は後半に書きました。そして**同じことを自動で調べる道具を同梱しています**。

### 自分で確かめられます

```sh
node tools/compat-probe/probe.mjs --model <プロバイダ>/<モデル> --tier full
```

対照実験を組んで送ります。1 回の試験で変える条件は 1 つだけ。たとえば `strict` の試験なら、同じスキーマで `required` の中身だけを変えた 2 通りを送り、結果の差を見ます。

出力はそのまま使える設定ファイルで、各項目に「いつ、何を送って、何が返ったか」が付きます。

```json
{
  "toolStrictMode": "drop",
  "_evidence": {
    "test_id": "T_TOOL_STRICT_REQUIRED_001",
    "tested_at": "2026-09-11T...",
    "request": "strict:true の関数ツール、required が limit を含まない",
    "response": "HTTP 400 invalid_request_error param=tools",
    "control": "同じスキーマから strict を外すと 200"
  }
}
```

**受理されただけでは「対応」と判定しません。** パラメータを受け取って黙って捨てる相手がいるからです。400 は気づけますが、200 を返して無視されると、本番で「なぜか検索しない」という形でしか現れません。そこで、パラメータが効いたかどうかが応答に現れる課題と必ず組にして送り、4 通りに分類します。

| 対照（指定なし） | 変種（指定あり） | 判定 |
|---|---|---|
| 効果なし | 効果あり | 効いている |
| 効果あり | 効果あり | 常に有効（指定は冗長） |
| 効果あり | 効果なし | 指定すると消える |
| 効果なし | 効果なし | **黙って無視されている** |

2 番目と 4 番目を区別しない道具は、正常な相手を「壊れている」と報告します。実際に一度やりました。

### 会話をまたいだ切り替え

GPT の思考内容は暗号化されていて他社のモデルへ渡せません。そのままでは、モデルを切り替えた瞬間に会話が途切れます。

この実装では、会話の要約を**両方のモデルが読める形式**に変換します。結果として、GPT が決めた条件を、切り替えた先のモデルがそのまま引き継げます。

実際の確認手順と結果です。

1. GPT に 4 桁の数字を 1 つ選ばせ、それを含むファイルの仕様を決めさせる
2. Muse に切り替えて「さきほど GPT が決めた条件どおりに」とだけ伝える
3. Muse が `# alpha-4729` を含む 8 行のファイルを作成
4. GPT に戻して検証させる → 合格

`4729` は人間が指定していません。会話が渡っていなければ出てこない数字です。途中で自動要約が 3 回走っていますが、条件は保持されました。

cd codex-router-zz
./install.sh codex

## 正直に書いておくこと

**無料枠はもう外部から使えません。** 2026-09-17 時点で、OpenCode は `muse-spark-1.3-contributor-free` を含む無料枠を自社クライアント以外に開放していません（HTTP 403）。2026-09-14 までは通っていたので、この間に方針が変わっています。**有料の `muse-spark-1.3` は同じ経路設定で動きます。**

**Contributor 版は Go の契約が要ります。** 学習データの提供に同意する代わりに安い版は Go 側にしか存在せず、Zen の残高だけでは届きません。同意も別途必要です。

**学習に使われる版があります。** `contributor` と名の付く版は、入力と出力が Meta のモデル学習に使われる可能性があると提供元が示しています。過去の会話やツールの実行結果も含まれます。**業務の機密情報を入れないでください。**

**未検証の項目があります。** コンテキスト長 `1048576` は公開メタデータの値で、実測では 22 万トークンまでしか確認していません。

**測定した拒否のうち 1 件は未対応です。** `tool_choice: "none"` はこのエンドポイントに拒否されますが、書き換える処理を入れていません。有料経路で約 100 ターン動かしても一度も送られてこなかったからです。Codex が送るようになれば壊れます。直し方は他の 6 件と変わりません。

**プロキシ経由の利用を制限する提供元があります。** 提供元の規約・レート制限・アカウント処分から利用者を守るものではありません。いずれの提供元とも提携していません。

## 仕組み（簡単に）

Codex は本来 OpenAI のサーバーに話しかけますが、設定を変えて**自分の PC 上の中継役**に話しかけさせます。中継役が中身を見て、GPT なら OpenAI へ、それ以外なら該当の提供元へ送り分けます。形式の違いもここで吸収します。

だから Codex 側は「いつもどおり」動いているつもりのまま、別のモデルが答えます。切り替えが一瞬なのはこのためです。
